NAIS3 셀프호스트 가이드

예약 생성을 백그라운드에서 계속 돌리고, PC와 폰이 같은 히스토리를 보게 하려면 내 서버(셀프호스트)가 필요합니다. 이 문서는 개인용 서버를 직접 세우는 두 가지 공식 방법을 안내합니다.

목차

  4. 트랙 B — Oracle Always Free (상시 무료 서버)

왜 서버 모드인가

NAIS3는 두 가지 방식으로 돌아갑니다. 로컬 모드는 설치 없이 브라우저에서 바로 쓸 수 있지만, 탭을 닫거나 기기가 잠들면 진행 중인 생성이 멈추고 데이터는 그 기기에만 남습니다. 서버 모드는 내 서버가 예약을 대신 실행하므로, 앱을 닫아도 생성이 이어지고 어느 기기에서 접속하든 같은 히스토리를 봅니다.

로컬 모드 서버 모드
시작 설치 없이 브라우저에서 바로 서버를 한 번 세워야 함
예약 생성 탭이 열려 있는 동안만 진행 (탭 닫힘·절전 시 중단) 서버가 상주하며 백그라운드로 계속 진행
데이터 위치 브라우저(기기)마다 따로 — 기기 간 공유 없음 서버 한 곳 — PC와 폰이 같은 히스토리
클라우드 저장 없음 (기기 저장소 한계) 서버가 곧 저장소 (원본이 서버에 남음)
비용 무료 내 PC면 0원 / VPS면 무료~소액

참고 서버 모드는 로컬 모드를 대체하지 않고 추가하는 선택지입니다. 서버를 꺼도 로컬 모드는 그대로 남습니다. NAI 토큰과 이미지는 내 서버에만 저장되며, 제작자는 코드만 배포합니다 (외부 서비스로 데이터가 가지 않습니다).

빠른 시작 (같은 PC에서 5분)

우선 내 PC 한 대에서 서버를 띄워 브라우저로 접속해 봅니다. 폰 접속은 트랙 A에서 이어집니다.

준비물

  • Node.js 20 이상 — nodejs.org에서 설치
  • git

1. 클론과 의존성 설치

git clone https://github.com/dd154663/NAIS3.git
cd NAIS3
npm ci

2. 빌드 (두 줄)

웹 프론트와 서버를 각각 빌드합니다. 서버가 웹 빌드를 함께 서빙하므로 둘 다 필요합니다. 

npm run build:web
npm run build:server

3. 실행

접속을 보호할 액세스 키를 정해 환경 변수로 넘깁니다 (길고 추측하기 어려운 값으로). 

# macOS · Linux
NAIS3_ACCESS_KEY=여기에-긴-키 node dist-server/nais3-server.cjs
# Windows (PowerShell)
$env:NAIS3_ACCESS_KEY="여기에-긴-키"; node dist-server/nais3-server.cjs

4. 접속

브라우저에서 아래 주소를 첫 방문 때 키와 함께 엽니다. 키는 브라우저에 저장되어 다음부터는 주소만으로 접속됩니다. 

http://127.0.0.1:8787/?serverKey=여기에-긴-키

환경 변수 서버 동작을 조정하는 값들입니다. 기본값으로도 동작합니다.

변수 의미 · 기본값
NAIS3_ACCESS_KEY 접속 액세스 키. 설정하면 외부(0.0.0.0) 접속 허용, 미설정 시 127.0.0.1 전용
NAIS3_PORT 포트 (기본 8787)
NAIS3_HOST 바인드 주소 (키 설정 시 0.0.0.0, 미설정 시 127.0.0.1)
NAIS3_DATA_DIR DB·이미지·암호화 키가 모두 들어가는 폴더 (기본 ~/.nais3-server)
NAIS3_WEB_DIST 서빙할 웹 빌드 경로 (기본 out/web)
NAIS3_APP_ROOT resources/가 있는 위치 (기본 현재 디렉터리)

트랙 A — PC + Tailscale 폰에서 접속

"컴퓨터를 켜 두고 나간 뒤 폰으로 확인"하는 패턴입니다. Tailscale은 내 기기들만 연결하는 사설망을 만들고, ts.net 도메인과 TLS 인증서를 자동으로 발급해 줍니다. 덕분에 서버는 그냥 평문 HTTP로 두고도 폰에서 https://로 안전하게 접속할 수 있습니다 (혼합 콘텐츠·PWA 설치 문제 해결).

1. Tailscale 설치 · 로그인

PC와 폰 양쪽에 Tailscale을 설치하고 같은 계정으로 로그인합니다. 그러면 둘이 같은 사설망(테일넷)에 들어옵니다.

2. 서버 실행

빠른 시작과 동일하게 서버를 띄워 둡니다 (액세스 키 포함).

NAIS3_ACCESS_KEY=여기에-긴-키 node dist-server/nais3-server.cjs

3. Tailscale로 포트 노출

PC에서 아래 명령으로 8787 포트를 테일넷에 TLS로 공개합니다.

tailscale serve --bg 8787

버전 주의 tailscale serve의 문법은 버전에 따라 다릅니다. 위 명령이 안 되면 tailscale serve --help로 현재 버전의 사용법을 확인하세요.

4. 폰에서 접속

폰 브라우저에서 PC의 테일넷 주소를 엽니다. 주소는 tailscale serve status 또는 Tailscale 관리 화면에서 확인할 수 있습니다. 

https://내기기이름.테일넷이름.ts.net/?serverKey=여기에-긴-키

서버가 웹 빌드를 함께 서빙하므로 접속 주소는 이 하나뿐입니다. 첫 방문 때 붙인 ?serverKey=는 브라우저에 저장되어 다음부터는 주소만으로 열립니다. https 뒤라 앱이 자동으로 wss(보안 웹소켓)를 씁니다.

절전 주의 PC가 잠들면 서버도 멈춰 예약이 진행되지 않습니다. 전원 옵션에서 절전·최대 절전을 끄거나, 최소한 예약이 도는 동안에는 화면만 꺼지고 시스템은 깨어 있도록 설정하세요.

Windows 자동 시작 (선택)

재부팅 후에도 서버가 자동으로 뜨게 하려면 작업 스케줄러에 "로그온 시 시작" 작업을 하나 만들고, 프로그램에 node, 인수에 dist-server/nais3-server.cjs, 시작 위치에 클론한 폴더 경로를 넣고, 환경 변수 NAIS3_ACCESS_KEY를 지정하면 됩니다.

트랙 B — Oracle Always Free 상시 무료 서버

PC를 계속 켜 두기 부담스럽다면, 항상 켜져 있는 무료 클라우드 서버가 좋습니다. Oracle Cloud의 Always Free Ampere A1 인스턴스는 arm64 4 OCPU / 24GB RAM에 블록 스토리지 200GB까지 무료라 이미지 용량 걱정이 없습니다. NAIS3의 arm64 스택 호환은 확인되었습니다.

유휴 회수 주의 무료 계정은 유휴 인스턴스를 회수하는 정책이 있습니다. 서버가 사라지지 않게 하려면 결제 수단을 등록해 PAYG(종량제)로 전환하세요. Always Free 한도 안에서 쓰면 요금은 계속 $0입니다.

1. 인스턴스 만들기

  • Shape: Ampere A1 (arm64), 이미지: Ubuntu LTS 등 최신 리눅스
  • A1은 인기가 많아 만들 때 용량 부족이 날 수 있습니다 — 잠시 뒤 재시도하거나 다른 가용 도메인을 선택하세요.

2. Node.js · git 설치와 클론

SSH로 접속한 뒤 Node 20+와 git을 설치하고 저장소를 클론합니다.

git clone https://github.com/dd154663/NAIS3.git
cd NAIS3

3. 의존성 설치 (Electron 없이)

서버 모드는 Electron이 필요 없습니다. Electron 바이너리 다운로드를 건너뛰고, 네이티브 모듈만 이 서버에 맞게 다시 빌드합니다. sharp는 arm64 프리빌트가 제공되어 그대로 동작합니다. 

ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci --ignore-scripts
npm rebuild better-sqlite3

4. 빌드

npm run build:web
npm run build:server

5. systemd 서비스로 상주시키기

서버가 재부팅·크래시 후에도 자동으로 다시 뜨게 systemd 유닛을 만듭니다. /etc/systemd/system/nais3.service에 아래 내용을 넣으세요 (경로·사용자·키는 본인 환경에 맞게). 

[Unit]
Description=NAIS3 self-host server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/NAIS3
Environment=NAIS3_ACCESS_KEY=여기에-긴-키
Environment=NAIS3_DATA_DIR=/home/ubuntu/.nais3-server
ExecStart=/usr/bin/node /home/ubuntu/NAIS3/dist-server/nais3-server.cjs
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now nais3
sudo systemctl status nais3   # 상태 확인

6. Tailscale로만 접속 (공개 포트 열지 않기)

인스턴스에도 Tailscale을 설치·로그인한 뒤, 트랙 A와 똑같이 포트를 테일넷에 공개합니다.

tailscale serve --bg 8787

이렇게 하면 Oracle의 보안 목록(Security List)이나 방화벽을 건드릴 필요가 없습니다. 공개 인터넷에는 포트를 하나도 열지 않고, 테일넷 안에서만 https://이름.ts.net으로 접속하니 NAI 토큰을 보관하는 서버가 외부에 노출되지 않습니다.

보안

서버 모드에서는 NAI 토큰이 서버에 저장됩니다. 토큰은 AES-256-GCM으로 암호화되어 DB에 들어가고, 복호화 키는 데이터 폴더 안의 userData/secret.key에 있습니다 (즉 DB와 secret.key는 한 세트). 토큰은 Anlas를 지출할 수 있는 권한이므로 서버가 뚫리면 잔고가 소진될 수 있습니다. 다음을 지키세요.

  • 서버는 반드시 사설망(Tailscale) 뒤에 두고, 공개 인터넷에 포트를 열지 마세요.
  • 액세스 키는 길고 추측 불가능하게 정하세요.
  • 공개 인터넷 노출은 권장하지 않습니다. 꼭 필요하면 고급 사용자 한정으로 리버스 프록시(Caddy 등) + TLS를 직접 구성하세요.

데이터와 백업

서버의 모든 상태 — DB, 이미지 원본, 암호화 키 — 는 NAIS3_DATA_DIR 한 폴더 아래에 모입니다 (기본 ~/.nais3-server). 백업은 이 폴더 하나만 복사하면 됩니다.

가장 안전한 백업 SQLite는 WAL 모드로 동작하므로, 서버를 잠깐 멈춘 뒤 폴더를 통째로 복사하는 것이 가장 안전합니다 (실행 중 복사는 파일이 어긋날 수 있습니다).

서버 모드에서는 자동저장을 켜 두는 것을 권장합니다. 원본이 서버에 남아야 나중에 폰에서 다시 열어 볼 수 있기 때문입니다 (Oracle 200GB면 용량 걱정도 없습니다).

업데이트

새 버전으로 올리려면 코드를 당겨 다시 빌드하고 서버를 재시작합니다.

git pull
npm run build:web
npm run build:server

직접 실행 중이면 서버를 껐다 다시 켜고, systemd라면 sudo systemctl restart nais3로 재시작합니다. 데이터 폴더는 그대로 유지됩니다.

문제 해결

증상 해결
"웹 빌드가 없습니다" 메시지 npm run build:web을 실행한 뒤 서버를 재시작하세요. 서버는 out/web을 서빙합니다.
401 또는 접속 실패 액세스 키가 맞지 않습니다. 주소에 ?serverKey=키를 다시 붙여 여세요 (키가 브라우저에 다시 저장됩니다).
상단에 "자동 재접속 중" 배너 서버가 켜져 있는지, 네트워크(테일넷 연결)가 정상인지 확인하세요. 앱은 연결이 돌아오면 자동으로 재접속합니다.
로컬 모드로 돌아가고 싶을 때 별도 서버 주소로 접속한 경우 주소에 ?server=off를 붙여 열면 로컬 모드로 복귀합니다. (서버가 직접 서빙한 페이지에는 해당 없음 — 그 주소는 서버 전용입니다.)

이 문서는 NAIS3 웹 빌드에 포함된 단일 가이드입니다 — /self-host.html.
